每推出一個新產品，團隊都需要準備一套後臺：誰來管理會員，誰能審核資金申請，運營如何發佈內容，客服如何處理用戶問題。這些需求在不同項目中反覆出現，佔用的交付精力也不斷累積。

我負責建設的 LHMS Framework，將這部分共性需求沉澱為通用業務中臺，並配套 LHMS Admin 管理後臺。它後來被複用到 OTC、BT CEX、Simple、SDH 等項目中，成為新產品可以直接繼承的業務管理基礎。

## 產品不同，後臺卻在重複建設

當時各項目獨立開發和部署。產品需要有自己的業務特色，但會員維護、內容發佈、權限分配等管理工作，大量沿用相似邏輯。

逐個項目建設這些功能，意味著同一類需求需要反覆開發和聯調，後續修復也要分別維護。我希望把已經解決過的共性問題保留下來，讓新項目的交付工作更多圍繞自身的核心業務展開。

## 關鍵判斷：統一到什麼程度

中臺的範圍需要控制。把所有產品規則都放進公共平臺，會讓不同項目互相牽制；只提供登錄和權限，又不足以減少實際業務中的重複建設。

我以可複用的管理流程劃定範圍：會員與代理關係維護、內容運營、資金申請處理、客服工單等進入通用中臺；交易品類、訂單規則及產品特有流程，由各項目繼續擴展。

例如，不同交易產品都需要查詢訂單、處理充值提現，但訂單如何產生、如何結算有各自的規則。因此，共用管理入口與基礎能力，同時保留具體業務邏輯的調整空間。各項目繼承這些能力後，仍然可以獨立部署和迭代。

## 在交易業務中複用，保留產品規則的差異

這套中臺所支撐的交易項目，以運營方集中管理賬號、訂單、資金申請和業務配置為主要形態。項目之間的相似度較高，因此把通用能力與派生業務放在一起介紹，更能說明同一個基礎平臺怎樣服務不同產品。

會員側的共性需求包括邀請關係、層級圖譜、多語言、消息通知、幫助中心與協議；運營側還涉及開閉市配置、VIP 權益和客服入口。不同產品可以選用這些能力，再按業務需要擴展，而不必每次重新建設整套後臺。

交易品類則保留在業務擴展中。例如，合約需要配置槓桿、最低購買量、手數及限價支持，現貨和股票也有各自的標的與訂單規則。限價檢查、持倉風險計算及強平屬於具體交易流程：業務系統接收行情後判斷訂單或賬戶是否滿足處理條件，再更新業務狀態、向用戶推送通知。行情接入與分發由 RateHub 提供，訂單判斷與處理仍由對應業務項目負責。

資金管理覆蓋多錢包、同幣種錢包間劃轉、多通道充值提現、審核記錄，以及分銷返佣等配置。業務人員需要同時識別會員、錢包、幣種、金額、通道和處理狀態；第三方資金通道的接入與後臺審核也各有職責。這些是業務覆蓋範圍，具體項目仍需分別定義劃轉、結算和異常恢復規則，不能僅憑存在管理頁面就認為已經保證資金一致性。

這裡展示的是通用平臺與派生項目共同覆蓋的業務範圍，並非每個項目都啟用了全部模塊，也不將後臺訂單處理等同於訂單簿撮合或鏈上協議執行。

## 從開源底座到可複用的業務平臺

LHMS Framework 基於 ruoyi-vue-pro 二次開發，採用 JDK 17 與 Spring Boot 3.x，並圍繞會員、運營、資金訂單及客服等實際場景，整理業務模塊與公共能力，為後續多個產品提供可複用的後臺基礎。

改造過程中，需要梳理原有能力之間的依賴。例如，登錄身份同時用於接口鑑權、操作日誌，以及業務記錄中創建人、修改人的自動填充。調整認證實現時，也需要銜接這些依賴，才能保證後臺操作仍然可以追溯到具體人員。

因此，我在擴展業務功能時，保留並銜接了統一的登錄上下文、權限校驗與審計字段填充機制。新接入的業務模塊可以沿用同一套身份識別和操作記錄方式，讓會員維護、資金審核等管理功能具備一致的權限邊界與操作追溯基礎，也減少了各項目重複處理這些基礎邏輯的工作。

## 可以實現哪些功能

中臺與配套後臺覆蓋以下業務能力，各項目根據產品範圍選用和擴展：

| 功能範圍 | 具體功能與使用場景 |
| --- | --- |
| 會員與代理管理 | 查詢和維護會員資料、調整賬號狀態、管理邀請關係與代理層級，支持業務人員維護客戶及其歸屬關係。 |
| 內容運營與通知 | 管理公告、新聞、輪播圖、廣告及多語言內容；維護郵件模板、短信與發送記錄，支持日常內容更新和用戶觸達。 |
| 錢包與資金管理 | 管理多錢包、同幣種錢包間劃轉、多通道充值提現申請及第三方資金通道；查看資金記錄、執行審核，並按項目配置分銷返佣規則。 |
| 行情與交易管理 | 管理交易標的、查詢報價和 K 線，並提供現貨、合約等訂單管理能力，供交易項目按自身業務規則使用和擴展。 |
| 客戶服務 | 收集用戶反饋、開展即時通信、維護快捷回覆，以及接入和結束工單，支持客服處理諮詢與跟進問題。 |
| 運營配置與數據 | 按產品配置開閉市、VIP 權益等規則；查看訪問趨勢、會員與資金相關統計，查詢明細及導出業務記錄。 |
| 後臺管理與權限 | 管理工作人員賬號、角色、菜單、操作權限和數據範圍；查詢操作日誌、管理文件，支持崗位分工與操作追溯。 |

## 從功能交付到日常運營

建設範圍同時覆蓋了業務後臺。配套的 LHMS Admin 在已有開源管理框架基礎上擴展，讓運營、審核和客服人員能夠實際使用這些能力。

以資金申請為例，審核人員可以從待處理記錄進入詳情，查看會員、金額、通道和狀態，再執行通過或駁回；處理記錄可供後續查詢。內容運營人員可以自行維護公告和輪播圖，客服則通過工單接入、處理並結束服務。崗位權限與操作記錄為這些日常工作提供邊界和追溯依據。

這些流程讓項目交付同時覆蓋用戶側功能和後臺管理，業務團隊獲得了開展運營所需的操作入口。

## 交付結果

LHMS Framework 與 LHMS Admin 形成了可複用的中臺及管理後臺，並落入多個派生項目。新項目可以繼承已有的會員、運營、訂單與客服能力，再補充自己的業務流程。

這種交付方式保留了產品獨立性，也留下了公共修復需要跨項目同步的維護成本。它在當時解決的具體問題，是讓已經交付過的管理能力能夠服務下一個項目。
